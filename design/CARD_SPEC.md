# カード教材の仕様（資格note・2026-11-25）

## 目的
長文が読めない人でも、**カードを順にめくって、はさまれた問題に答えていくだけで、このレッスンの問題がすべて解ける**ようにする。
今の長文（lessons.json の sections）は「くわしく読む」として残す。カードはそれを短く切り分けたもの。

## 入力
`design/card_pack/<exam>/<lessonId>.md`：今の本文（長文）と、このレッスンの全問題（◎正解・×誤り・解説・×の理由）。

## 出力
`design/cards_v1/<exam>/<lessonId>.json`（UTF-8・JSONとして正しいこと）
```json
{
  "id": "l-th1",
  "units": [
    {
      "title": "区切りの名前（14字以内）",
      "goal": "この区切りで分かるようになること（40字以内）",
      "cards": [
        {"t": "point", "head": "見出し（16字以内）", "body": "本文（150字以内）", "ex": "例（任意・80字以内）"},
        {"t": "quiz", "q": "b-th1-01"}
      ]
    }
  ]
}
```

## 区切り（unit）
- 1区切り＝**約3分**。point カード4〜7枚＋quiz 2〜3問が目安。
- 意味のまとまりで切る（3分・5問で機械的に切らない）。前提が次の区切りに流れないようにする。
- 順番は「基本 → 応用 → 紛らわしいものの区別」。

## point カード
- **1枚に言いたいことは1つ**。body は150字以内、文は1文40字前後まで。です・ます調。
- 1枚目の1文目で「何の話か」が分かるようにする。前置き・あいさつは書かない。
- 並べて比べるときは行頭「・」の箇条書き（改行は \n）を使ってよい。最大4行。
- 専門用語は初めて出たときに一言で意味を書く。
- ex には具体的な数値例・身近なたとえを1つ。無理に付けない。
- Markdown記号（#、**、|）・絵文字は使わない。

## quiz カード（問題をはさむ）
- レッスンの**基礎問題（b-）を全部**、どこかの区切りにはさむ。確認問題（q-）・ドリル（d-）ははさまない（カードの後でいつもどおり解く）。
- 例外：基礎問題が1問も無いレッスン（Dify など）は、材料の「はさむ問題」から各区切りに1〜2問ずつはさむ（全部でなくてよい・各問1回まで）。
- 各問題は、**それを解く根拠が書いてある point カードの後**に置く。根拠より前に置かない。
- point カード2〜3枚ごとに1問が目安。最初の問題は区切りの3枚目までに出す（すぐ「できた」がある）。

## 削ってはいけないもの（最重要）
- **このレッスンの全問題（b-・q-・d-）を、カードだけを読んで解ける**こと。長文の要約ではない。
- 数値・範囲・例外（「ただし」「〜の場合は」）・手順の順番・紛らわしい言葉との違いは、問題に関係するものは**すべて**カードに残す。足りなければカードを増やす。
- ×の理由に出てくる「よくある間違い」は、違いが分かるカードにする（例：「n倍ではなく2のn乗倍」）。
- 書いてよい事実は入力ファイルにあるものだけ。自分の知識で数値・名前・仕様を足さない。
- 問題文をそのまま写さない。「正解は」「問題で問われる」などメタな言い方もしない。

## 出力前に自分で確かめること
1. 全問題について「カードだけ読んだ人が×を外して◎を選べるか」を頭の中で解く。
2. quiz の位置が、その根拠カードより後になっているか。
3. body が150字以内か、基礎問題がすべて入っているか、JSONとして正しいか。
4. 入力の食い違いや、おかしいと思った問題は `design/cards_v1/<exam>/_notes.md` に1行で残す。

検査：`python -I design/card_tools.py check <exam>/<lessonId>`（字数・基礎問題の網羅・ID・順番）。
本当の合否は、別の採点係が**カードだけを根拠に全問を解いて**決める。
