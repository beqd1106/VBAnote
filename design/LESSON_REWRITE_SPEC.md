# レッスン本文の書き直し仕様（資格note）

## 目的（これだけは外さない）
**このレッスンを読んだ人が、このレッスンの問題をすべて解ける**ようにする。
いまの本文は用語を並べただけで短く、問題の正解の言葉が2〜3割しか載っていない。利用者から「教材を読んでも問題がわからない」と言われている。

「解ける」とは次の2つを両方満たすこと：
1. 正解の選択肢を選べる（その言葉・数値・手順が、意味と一緒に本文に書いてある）
2. 間違いの選択肢を外せる（紛らわしい別の言葉との**違い**が本文に書いてある）

## 入力
`design/lesson_pack/<exam>/<lessonId>.md`：現在の本文と、このレッスンの全問題（◎が正解、×が誤り、解説、×の理由、出典）。

## 出力
`design/lesson_v2/<exam>/<lessonId>.json`（UTF-8、JSONとして正しいこと）：
```json
{
  "id": "l-sc1",
  "summary": "このレッスンで分かるようになることを1〜2文で（80字以内）",
  "sections": [
    {"heading": "見出し（20字以内・内容が分かる名詞句）", "body": "本文"}
  ]
}
```
- `id` は入力と同じ。タイトル・分野・問題IDは変えない（出力に含めない）。
- 「出題ポイント」という見出しの節は作らない（別のスクリプトが自動で付ける）。

## 書き方
- 節は **3〜8個**。問題で問われる内容を、意味のまとまりごとに節に分ける。順番は「基本 → 応用 → 紛らわしいものの区別」。
- 1つの節は **200〜1,500字** が目安。全体は問題の量に応じて **1,500〜7,000字**（問題が100問を超えるレッスンは10,000字まで）。
- **水増し禁止**：「まとめ直し」「言い回しの違い」など、前の節の内容を言い換えて並べ直すだけの節は作らない。選択肢の言い回しを拾うためだけの文も書かない。同じ事実は1か所に書く。
- 文は短く。1文60字前後まで。です・ます調。
- 専門用語は初めて出たときに一言で意味を書く。例：「BCP（事業継続計画＝災害時でも仕事を止めないための計画）」
- **紛らわしい組み合わせは並べて違いを書く**。例：「OJTは職場で仕事をしながら学ぶ。OFF-JTは職場を離れて研修などで学ぶ」。×の理由に出てくる「別の言葉」は、そのための材料。
- 並べて比べる内容は、行頭「・」の箇条書きにしてよい（改行は \n）。表やMarkdown記号（#、**、|）は使わない。
- 数値・名前・手順・画面の場所・オプション名は、問題で問われているものは**正確に**本文へ入れる。
- 具体例を1つ添えると理解しやすい箇所には、短い例を入れる。
- 問題文をそのまま写さない（答えの暗記帳ではなく、仕組みが分かる文章にする）。「問題で問われる」「正解は」などメタな言い方もしない。
- 絵文字は使わない。

## 事実の扱い（最重要）
- 書いてよい事実は、**入力ファイルにあるもの（現在の本文・問題・解説・×の理由・出典・マニュアル抜粋）だけ**。
- 自分の知識で新しい数値・版数・年・料金・仕様・機能名を足さない。言い換え・つなぎの説明・身近なたとえはよい。
- 入力の中で食い違いがあれば、多数の解説が支持する方を書き、`design/lesson_v2/<exam>/_notes.md` に「問題ID・食い違いの内容」を1行で残す。
- 正解の解説が明らかにおかしいと思った問題も、同じく `_notes.md` に残す（本文には書かない）。

## 自分で確かめること（出力前）
1. ◎の選択肢の言葉（括弧や読点の前まで）が、ほぼすべて本文に入っているか。
2. 各問題について「本文だけ読んだ人が、×を外して◎を選べるか」を頭の中で解いて確かめる。
3. JSONとして正しいか（`python -c "import json;json.load(open(...,encoding='utf-8'))"`）。

確認用スクリプト：`python design/check_lessons.py <exam>/<lessonId> ...` が正解語・誤答語の掲載率と字数を出す。正解語の掲載率は**85%以上**を目安にする。足りない言葉は、それが**知識として必要なら**意味と一緒に本文の適切な節へ足す。答えが長い文の選択肢（例：「指定したファイル名でシナリオを保存し終了する」）は言葉が一致しなくてよいので、その内容が本文から分かれば十分。
本当の合否は、別の採点係が**本文だけを根拠に問題を解いて**決める（design/judge_pack.py）。キーワードの数を合わせることより、読んで解けることを優先する。
