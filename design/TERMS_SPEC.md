# 用語カード・用語集・頻出キーワードの作成仕様

指定された資格について、次の3ファイルを UTF-8 の JSON 配列で、指定フォルダ（例 `.../FEnote/design/src/`）に保存する。
1ファイル書き終えるごとに保存すること（最後にまとめない）。

## 1. terms.json（用語カード 45件）
```json
{"id": "t-key1", "term": "用語", "shortDescription": "一言で（30字以内）",
 "beginnerExplanation": "完全初心者向けのかみ砕いた説明。身近な例えを入れる（80〜150字）",
 "useCase": "実務や試験でどう使われるか（50〜100字）",
 "examPoint": "試験で問われやすいポイント・混同しやすいものとの区別（50〜100字）",
 "relatedServices": ["関連語1", "関連語2"], "domain": "分野キー", "difficulty": 1}
```
- id は **最重要の6語を t-key1〜t-key6**、残りを t-001 から連番。
- domain は指定の分野キーのいずれか。全分野にバランスよく配分（分野ごと最低4件）。
- difficulty は 1〜3。

## 2. glossary.json（用語集ツールチップ 70件）
```json
{"term": "用語", "explanation": "問題文中でタップしたときに出す短い説明（25〜60字）"}
```
- 問題文・解説に頻出する専門用語・略語。term は実際に文中に現れる表記（略語は略語のまま）。
- 1〜2文字の短すぎる語や、一般語（「データ」「処理」など）は入れない。term の重複禁止。

## 3. services.json（頻出キーワード一覧 36件）
```json
{"id": "s-001", "name": "名称", "category": "カテゴリ名", "oneLiner": "1行説明（40字以内）", "domain": "分野キー"}
```
- category は4〜8種類程度にまとめる（例：FEなら「計算式」「略語」「プロトコル」など）。
- 全分野にバランスよく配分。

## 品質
- 事実の正確さを最優先。自信のない細かい数値・バージョン固有の仕様は書かない。
- 絵文字・Markdown記号は使わない。説明は「です・ます」調でなくてよい（体言止め可）が、ファイル内で統一する。
完了したら3ファイルのパスと件数だけ報告する。

## 再開ルール
保存先フォルダにすでに terms.json / glossary.json / services.json がある場合、件数がそろっているものは残し、無いもの・足りないものだけ作る。
