×3: これはメモリのアクセス時間の説明である。時間の単位で表す指標で、1秒あたりの回数を表す周波数とは異なる。

## b-cs1-08

## b-cs1-09

×3: PaaSはアプリケーションの開発・実行環境を借りる形態で、利用者が自分のアプリを載せて動かします。
×4: オンプレミスは自社の設備内にシステムを設置して運用する形態で、クラウドの利用形態ではありません。

## b-cs2-04
問題: 1台の物理サーバの上で、複数の独立したOSやサーバを動かす技術はどれか。

×2: 負荷分散は複数のサーバへ処理を振り分ける技術で、1台を複数に見せる仮想化とは方向が反対です。
×3: ストライピングはRAID0のようにデータを複数のディスクへ分散して書く方式で、サーバの仮想化ではありません。

## b-cs2-05
問題: RAID0（ストライピング）の特徴として適切なものはどれか。
1. ◎複数台に分散して書き込むため高速だが、1台の故障で全データを失う
2. 同じデータを2台に同時に書き込み、1台が故障してもデータを保持する
3. パリティを分散して記録し、1台の故障ならばデータを復元できる
4. 2台のうち1台を待機させ、故障したときだけ切り替えて使用する
解説: RAID0は、データを分割して複数のディスクに交互に書き込むため、読み書きが速く、容量も全台分使えます。ただし冗長性がなく、1台でも壊れると全体が読めなくなります。速度が上がっても耐障害性は上がらない点が、RAID1やRAID5との大きな違いです。
×2: これはRAID1（ミラーリング）の説明です。同じ内容を複製するため、使える容量は半分になります。
×3: これはRAID5の説明です。パリティによって1台分の故障から復元でき、RAID0にはその仕組みがありません。
×4: 待機系を用意して切り替える方式はRAIDの構成ではなく、デュプレックスシステムの考え方です。

## b-cs2-06
問題: 2台のディスクに同じデータを同時に書き込み、1台が故障しても運用を続けられるRAIDはどれか。
1. RAID0
2. ◎RAID1
3. RAID5
4. RAID6
解説: RAID1はミラーリングとも呼ばれ、2台のディスクに同一のデータを同時に書き込みます。1台が壊れても残る1台で運用を続けられますが、使える容量は搭載した容量の半分になります。分散して書くだけのRAID0や、パリティを使うRAID5と混同しないようにします。
×1: RAID0は分散して書き込むだけで冗長性がなく、1台故障するとデータをすべて失います。
×3: RAID5はパリティを使い3台以上で構成します。2台に同一データを書く仕組みではありません。
×4: RAID6はパリティを2種類記録して2台の同時故障まで耐えられますが、4台以上が必要で構成が異なります。

## b-cs2-07
問題: RAID5の特徴として適切なものはどれか。
1. 全データを2台に同時に書き込み、使える容量が常に半分になる
2. データを分割して書き込むだけで、故障時の復元手段を持たない
3. ◎データとパリティを分散して記録し、1台の故障ならば復元できる
4. パリティを専用の1台に集め、2台が同時に故障しても復元できる
解説: RAID5は、データと誤り訂正用のパリティを3台以上のディスクに分散して記録します。1台が故障しても、残りのデータとパリティから失われた内容を計算で復元できます。ただし復元できるのは1台までで、2台が同時に壊れるとデータを失います。
×1: これはRAID1の説明です。RAID5では3台以上を使い、パリティ分の1台分だけ容量が差し引かれます。
×2: これはRAID0の説明です。RAID0には冗長性がなく、1台でも壊れるとデータを失います。
×4: パリティは専用の1台ではなく全ディスクに分散します。また2台同時の故障には耐えられません。

## b-cs2-08
問題: 1TBのハードディスク4台でRAID5を構成したとき、データを保存できる容量はおよそ何TBか。
1. 4TB
2. 2TB
3. 1TB
4. ◎3TB
解説: RAID5ではパリティの記録に1台分の容量を使うため、n台構成の使える容量は(n−1)台分です。4台なので(4−1)×1TB=3TBになります。4TBが使えるのは冗長性のないRAID0、半分の2TBになるのはミラーリングのRAID1の場合です。
×1: 全台分を使えるのはRAID0の場合で、RAID5ではパリティ分として1台分が差し引かれます。
×2: 半分になるのはRAID1の考え方で、RAID5は4台構成なら(4−1)台分が使えます。
×3: 1台分しか使えないのは差し引きすぎで、RAID5でパリティに使うのは全体のうち1台分だけです。

## b-cs2-09
問題: MTBFの説明として適切なものはどれか。
1. ◎故障から次の故障までの間、正常に動いた時間の平均値
2. 故障が発生してから修復が完了するまでの時間の平均値
3. システムが処理を開始してから結果を出すまでの時間の平均
4. 一定期間内に発生した故障の回数を合計した値
解説: MTBFは平均故障間隔のことで、システムが故障せずに動き続ける時間の平均値です。値が大きいほど故障しにくい信頼性の高いシステムといえます。修復にかかる時間の平均はMTTRで、MTBFとは逆に値が小さいほど望ましい指標です。
×2: これはMTTR（平均修復時間）の説明です。MTBFは修復ではなく、正常に動作している時間を表します。
×3: 処理の開始から結果が出るまでの時間はレスポンスタイムなどの性能指標で、信頼性の指標ではありません。
×4: MTBFは回数の合計ではなく、故障と故障の間の時間の平均です。故障回数は直接の定義ではありません。

## b-cs2-10
問題: MTTRの説明として適切なものはどれか。
1. 故障が起きてから次の故障が起きるまでの時間の平均値
2. ◎故障してから修復が完了するまでにかかる時間の平均値
3. 運用時間全体のうち、正常に動作していた時間の割合
4. 利用者が操作してから画面に応答が返るまでの時間の平均
解説: MTTRは平均修復時間のことで、故障が起きてから復旧するまでにかかる時間の平均値です。値が小さいほど早く直る、保守性の高いシステムといえます。稼働率は、MTBFをMTBFとMTTRの合計で割って求めるため、MTTRが短いほど高くなります。
×1: これはMTBF（平均故障間隔）の説明で、修復時間ではなく正常に動いた時間を表す指標です。
×3: 運用時間に対する正常稼働の割合は稼働率で、MTBFとMTTRから計算して求める別の指標です。
×4: 操作から応答が返るまでの時間はレスポンスタイムという性能の指標で、故障の修復とは無関係です。

## b-cs2-11
問題: MTBFが400時間、MTTRが100時間のシステムの稼働率はどれか。
1. 0.2
2. 0.25
3. 4.0
4. ◎0.8
解説: 稼働率はMTBF÷(MTBF+MTTR)で求めます。400÷(400+100)=400÷500=0.8です。0.2は停止している時間の割合、0.25はMTTRをMTBFで割った値、4.0はMTBFをMTTRで割った値で、いずれも稼働率の式とは異なります。
×1: 0.2は100÷500の値で、停止している時間の割合（不稼働率）です。稼働率はその残りの0.8です。
×2: 0.25は100÷400で、分母をMTBFだけにした誤りです。分母はMTBFとMTTRの合計になります。
×3: 4.0は400÷100で、MTBFをMTTRで割った値です。稼働率は1を超えることはありません。

## q-cs2-01
問題: 稼働率が0.95の装置Aと、稼働率が0.90の装置Bを直列に接続したシステム全体の稼働率はどれか。
1. 0.995
2. 0.925
3. 0.145
4. ◎0.855
解説: 直列構成は両方の装置が動いて初めて正常なので、各稼働率の積になります。0.95×0.90=0.855です。0.995は並列構成の値(1−0.05×0.10)、0.925は単純な平均で、どちらも直列の計算ではありません。直列は必ず単体より低くなります。
×1: 0.995は1−(1−0.95)×(1−0.90)で求める並列構成の値です。直列では片方の故障で全体が止まります。
×2: 0.925は2つの稼働率の平均で、構成を考えない誤りです。直列では積を求めます。
×3: 0.145は2つの故障率（0.05と0.10）の合計に近い値で、稼働率ではありません。

## q-cs2-02
問題: 稼働率が0.8の装置Aと、稼働率が0.9の装置Bを並列に接続し、どちらか一方が動けば正常とみなすシステム全体の稼働率はどれか。

2. 0.72
3. 0.85
4. 0.90

×2: 0.72は0.8×0.9で求める直列構成の値です。並列は片方が動けばよいので、これより高くなります。
×3: 0.85は2つの稼働率の平均で、並列構成の計算ではありません。並列は両方が停止する確率を使います。
×4: 0.90は稼働率の高い方の装置だけの値です。並列にすると、もう一台が補うためそれより高くなります。

## q-cs2-03
問題: 稼働率0.9の装置Aに、稼働率0.8の装置BとCを並列に接続した部分を直列につないだシステム全体の稼働率はどれか。

4. 0.576

## q-cs2-04

4. ◎0.99

×1: 0.81は0.9×0.9で、2台を直列に接続した場合の値です。並列なら単体の0.9より高くなります。
×2: 0.90は装置1台の稼働率です。2台を並列にした効果が反映されておらず、冗長化の意味がなくなります。
×3: 0.999は3台を並列にしたときの値(1−0.1×0.1×0.1)です。この問題は2台なので0.99になります。

## q-cs2-07
問題: RAID5で構成した4台のディスクのうち、2台が同時に故障した場合の状態として適切なものはどれか。

2. 故障した2台の分だけを失い、残りのデータは正常に読み出せる

4. ◎パリティでは復元できず、ディスク全体のデータを失う

2. ◎CPUや主記憶などの資源を管理し、アプリケーションに割り当てる
3. ネットワーク上の他のコンピュータからの不正な通信だけを遮断する
4. プログラムのソースコードを機械語に変換して、実行形式にまとめる
解説: OSはCPU、主記憶、入出力装置などの資源を管理し、複数のアプリケーションへ割り当てて動作を支えます。そのためアプリは機器の細かな違いを意識せずに済みます。文書作成などの業務処理はアプリケーション、機械語への変換は言語プロセッサの役割で、OSとは別物です。
×1: 文書作成や表計算は応用ソフトウェアの役割です。OSはそうした業務処理の土台として資源を管理します。
×3: 不正な通信の遮断はファイアウォールなどの役割です。OSは通信の遮断専用ではなく資源全般を管理します。
×4: 機械語への変換は言語プロセッサ（コンパイラなど）の役割です。OSは変換後のプログラムを動かす側です。

## b-cs3-02
問題: ラウンドロビン方式によるタスクのスケジューリングの説明はどれか。
1. 優先度の高いタスクから順に、終了するまでCPUを割り当てる
2. 到着した順にタスクを並べ、先頭から終了まで実行していく
3. ◎一定時間ごとにタスクを順番に切り替え、CPUを割り当てる
4. 処理時間の短いタスクを優先して、先にCPUを割り当てていく
解説: ラウンドロビンは、決まった時間（タイムスライス）ずつ各タスクへ順番にCPUを割り当て、使い切ると待ち行列の最後尾に回す方式です。待ち時間が公平になり、対話型の処理に向きます。優先度で決める方式や、到着順に終了まで実行する方式とは区別します。
×1: これは優先度方式の説明です。ラウンドロビンはタスクに優先順位をつけず、公平に順番で回します。
×2: 到着順に終了まで実行するのは到着順方式です。ラウンドロビンは時間で区切って切り替えます。
×4: 処理時間の短いものを優先するのは最短処理時間優先方式です。ラウンドロビンは長さを見ずに順番に回します。

## b-cs3-03
問題: 優先度方式のスケジューリングに関する記述として、適切なものはどれか。
1. ◎優先度の高いタスクほど、先にCPUが割り当てられやすくなる
2. 全てのタスクに同じ長さの時間を順番に割り当てて切り替える
3. 後から到着したタスクを先に実行し、順番を逆にして処理する
4. 主記憶に読み込まれた順に、古いタスクからCPUを割り当てる
解説: 優先度方式では、各タスクに付けた優先度に従い、高いタスクから先にCPUを割り当てます。緊急の処理を先に終わらせたいときに使われます。同じ長さの時間で順番に回すラウンドロビン方式とは異なり、優先度の低いタスクは後回しにされます。
×2: 同じ時間ずつ順番に割り当てるのは、ラウンドロビン方式の説明です。優先度方式では優先度で順番が決まります。
×3: 到着の逆順に処理するのは後入れ先出し（LIFO）の考え方です。優先度方式は到着順ではなく優先度で決めます。
×4: 古い順に割り当てるのは到着順（先入れ先出し）の考え方です。優先度方式の判断基準は優先度です。

## b-cs3-04

×2: ページングは、プログラムを固定長のページに区切って管理する仮想記憶の方式です。

## b-cs3-05
問題: 仮想記憶の目的として、適切なものはどれか。

2. ◎補助記憶を利用して、主記憶の容量より大きなプログラムを実行可能にする
3. CPUの内部に高速な記憶領域を置き、主記憶の読出しを速くする
4. 複数のディスクにデータを分散して書き込み、読書きの速度を上げる
解説: 仮想記憶は、補助記憶の一部を主記憶の延長として使い、実際の主記憶より大きなプログラムでも実行できるようにする仕組みです。主記憶の複製は障害対策、高速な領域はキャッシュメモリ、分散書込みはRAID 0の話で、どれも仮想記憶の目的ではありません。
×1: 主記憶の複製を予備として持つのは、障害対策のための二重化やバックアップの考え方です。
×3: CPU内の高速な記憶領域は、主記憶の読出しを速めるキャッシュメモリです。
×4: データを分散して書き込み速度を上げるのは、RAID 0（ストライピング）の仕組みです。

## b-cs3-06
問題: ページング方式の仮想記憶において、プログラムを区切る単位はどれか。

×4: ディレクトリはファイルを整理する入れ物で、仮想記憶の単位ではありません。

## b-cs3-07
問題: 仮想記憶において、アクセスしたページが主記憶に存在しないときに発生する事象はどれか。
1. スラッシング
2. デッドロック
3. スワップアウト
4. ◎ページフォールト
解説: ページフォールトは、必要なページが主記憶にないときに起こる事象で、OSが補助記憶から主記憶へそのページを読み込んでから実行を再開します。スラッシングはページの入替えが多すぎて処理が進まない状態で、ページフォールトが大量に続いた結果として現れる別の現象です。
×1: スラッシングは、ページフォールトが頻発して処理が進まなくなる状態です。1回の事象を指す語ではありません。
×2: デッドロックは、複数の処理が互いの資源の解放を待ち続けて止まる状態です。
×3: スワップアウトは、使われていない領域を補助記憶へ書き出す動作で、存在しないページへの参照で起こる事象ではありません。

## b-cs3-08
問題: ページ置換アルゴリズムFIFOで、置換の対象となるページはどれか。
1. ◎主記憶に最も長く存在しているページ
2. 最も長い間参照されていないページ
3. 最も多く参照されているページ
4. 最後に主記憶へ読み込まれたページ
解説: FIFO（先入れ先出し）は、主記憶に読み込まれてからの経過時間が最も長いページを追い出す方式です。参照の頻度や時期は見ません。最も長く参照されていないページを追い出すのはLRUで、両者は「読み込まれた時期」か「最後に使った時期」かで区別します。
×2: 最も長い間参照されていないページを追い出すのはLRUです。FIFOは参照ではなく読込みの古さで決めます。
×3: 参照回数の多さでは判断しません。FIFOは最も古く読み込まれたものを追い出します。
×4: 最後に読み込まれたページは最も新しいページで、FIFOでは最後まで残ります。

## b-cs3-09
問題: ページ置換アルゴリズムLRUで、置換の対象となるページはどれか。
1. 参照された回数が最も多いページ
2. ◎最も長い間参照されていないページ
3. 最後に参照されたページ
4. 主記憶へ最初に読み込まれたページ
解説: LRU（Least Recently Used）は、最後に参照されてからの経過時間が最も長いページを追い出す方式です。最近使われたページは近いうちにも使われやすいという性質を利用します。読み込まれた順で決めるFIFOとは、基準が「参照」か「読込み」かで異なります。
×1: 参照回数が多いページは、よく使われているため追い出す対象にはなりません。
×3: 最後に参照されたページは最も新しく使われたもので、LRUでは最後に追い出されます。
×4: 最初に読み込まれたページを追い出すのはFIFOです。LRUは参照の古さで決めます。

## b-cs3-10

## b-cs3-15
問題: 2入力のAND回路が1を出力するのは、どのような場合か。

## q-cs3-02
問題: 3つのページフレームを持ち、FIFOでページを置換する仮想記憶で、ページの参照順が 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 のとき、ページフォールトは何回起こるか。ただし、最初は全てのフレームが空である。

2. 10回
3. ◎9回
4. 12回

## q-cs3-04

解説: 「..」で一つ上の /home/user に上がり、そこから images/a.png をたどるので、相対パスは ../images/a.png です。相対パスは現在地が起点であり、「.」は現在のディレクトリ、「..」は一つ上を表します。起点がルートの絶対パスとは書き方が異なります。
×1: ./images/a.png は docs の下の images を指し、/home/user/docs/images/a.png になります。
×2: ../../images/a.png は二つ上の /home に上がるため、/home/images/a.png を指してしまいます。
×3: images/a.png は ./ を省略した形で、docs の下の images を指します。一つ上に上がっていません。
